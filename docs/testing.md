# 테스트

"무엇을 고쳤을 때 무엇을 돌리고 무엇을 더 써야 하는가"를 정리한다.

## 한 줄 요약

```bash
pnpm quality   # 서식 → lint → 바인딩 타입 → 타입 검사 → 단위·통합 테스트
```

브라우저·시뮬레이터가 필요한 e2e는 여기 들어가지 않는다(`pnpm test:e2e`).
환경에 좌우돼 캐시할 수 없고, 바꾼 화면에 대해서만 돌리는 편이 낫기 때문이다.

## 무엇을 고쳤는가 → 무엇을 돌리는가

| 고친 곳                 | 돌릴 것                                          | 더 써야 할 것                                      |
| ----------------------- | ------------------------------------------------ | -------------------------------------------------- |
| `packages/shared`       | `pnpm --filter @leave/shared test`               | 규칙마다 vitest 단위 테스트 (경계값을 반드시 포함) |
| `packages/client` 훅·폼 | `pnpm --filter @leave/client test`               | 무효화·세션 전환은 `test/*.test.tsx` 패턴을 따른다 |
| `apps/api` 라우트·lib   | `pnpm --filter @leave/api test`                  | 통합 테스트(HTTP). 목으로 대체하지 않는다          |
| `apps/admin` worker     | `pnpm --filter @leave/admin test`                | `scripts/run-tests.mjs`에 요청 왕복을 추가         |
| `apps/admin` 화면       | `check-types` + `lint` + 브라우저 확인           | 중요한 흐름이면 `e2e/admin.spec.ts`                |
| `apps/web` 화면         | `check-types` + `lint` + 브라우저 확인           | 중요한 사용자 여정이면 Playwright                  |
| `apps/native` 화면      | `check-types` + `lint`                           | 중요한 흐름이면 Maestro                            |
| `wrangler.jsonc` 바인딩 | `pnpm --filter <앱> types` 후 `pnpm types:check` | —                                                  |

## 계층별 성격

**`packages/shared` — vitest 단위 테스트.**
순수 함수라 입력·출력만 보면 된다. 여기 테스트가 가장 촘촘해야 한다 —
서버와 두 앱이 이 답을 그대로 믿는다. 날짜 경계(월말, 연말, 전역일, 주기 경계)를 반드시 넣는다.

**`packages/client` — vitest + `@testing-library/react`.**
지키려는 것이 "무엇을 계산하는가"가 아니라 "성공 후 어떤 캐시를 비우고 어댑터의 무엇을 부르는가"라서
훅을 실제로 렌더한다. 하네스는 `test/react-query.tsx`이고, 가짜 client에는 훅이 부르는 경로만 담으면 된다.
무효화 테스트는 키 이름이 아니라 실제 캐시 상태(`isInvalidated`)로 확인한다 —
키 목록을 그대로 베끼면 목록이 틀렸을 때 테스트도 같이 틀린다.

**`apps/api` — 실제 D1에 붙는 통합 테스트.**
`scripts/run-tests.mjs`가 격리된 상태로 마이그레이션을 적용하고 `wrangler dev`를 띄운 뒤 HTTP로 두드린다.
목으로 바꾸지 않는다 — 이 프로젝트에서 실제로 났던 사고 대부분(외래키 정리 누락, 초대코드 동시 소진,
캐시 무효화 누락)은 SQL과 요청 순서가 얽힌 자리에서 나왔고, 목은 그 자리를 통과시킨다.
서비스 단위 테스트를 더할 수는 있지만 통합 테스트를 대체하지는 않는다.

**`apps/admin` — 워커 통합 테스트 + Playwright.**
`scripts/run-tests.mjs`가 로그인부터 감사 로그까지 한 번에 돈다.
라우트 모듈을 추가하면 목록 요청을 하나 추가한다 — 마운트를 빠뜨리면 화면에서는 빈 표로만 보이고
조용히 넘어간다.

**웹·앱 — 중요한 여정만.**
표시 문구 하나까지 e2e로 굳히지 않는다. 깨졌을 때 사용자가 못 쓰게 되는 흐름만 남긴다.
친구 기능은 요청 수락 전후·삭제·차단 권한을 실제 D1 API 테스트로 고정하고, 화면 e2e에서는 친구 탭,
10명 선택 제한, 비교 달력과 개인 일정 생성·수정·삭제를 확인한다. 다른 사람의 개인 일정이나 비공개 휴가
필드가 새는지 여부는 UI가 아니라 API 응답 자체를 검사한다.

사용자 이름과 친구 상태 기계는 세 층에서 함께 고정한다. 규칙(정규화·허용 문자·경계)은
`packages/shared/test/username.test.ts`, 유일성 경합과 응답의 필드 최소화는
`apps/api/test/username.test.mjs`·`user-search.test.mjs`, "친구를 끊으면 다음 요청이 곧바로
403"은 `apps/api/test/friends.test.mjs`가 맡는다. **반대 방향 요청이 자동 수락되지 않는다**는
회귀 테스트가 그중 가장 중요하다 — 예전 동작이 그 자리에서 되돌아오면 받는 사람의 동의 없이
일정이 공개된다.

## 위험한 것을 고칠 때

다음을 고칠 때는 **먼저** 지금 동작을 고정하는 테스트가 있는지 확인하고, 없으면 만든 뒤에 손댄다.

- 회원 탈퇴 (`lib/delete-account.ts`) — 되돌릴 수 없고, 무엇이 지워지는지가 곧 개인정보 약속이다
- 그룹 가입·탈퇴 (`lib/unit-membership.ts`) — 동시 요청이 초대코드 상한을 넘길 수 있다
- 휴가 병합·잔여 (`lib/leave-merge.ts`, `lib/leave-balances.ts`)
- 관리자 권한 판정 (`worker/auth.ts`)와 감사 로그
- 클라이언트 캐시 무효화 (`hooks/invalidate.ts`)
- 보관 기간 정리 (`lib/retention.ts`) — 지우면 안 되는 것을 지우면 되돌릴 수 없다

절차는 같다. ① 지금 동작을 그대로 적은 테스트를 쓴다 ② 그 테스트가 **고치기 전** 코드에서 통과하는지 본다
③ 고친다 ④ 같은 테스트가 여전히 통과하는지 본다.
②를 건너뛰면 "무엇을 지키는지 모르는 테스트"가 남는다.

## 커버리지에 대해

숫자를 목표로 삼지 않는다. 분기가 많은 도메인 규칙, 권한, 되돌릴 수 없는 삭제, 날짜 경계,
부수효과가 있는 뮤테이션을 먼저 덮는다. 화면 보일러플레이트를 덮으려고 테스트를 쓰지 않는다.
