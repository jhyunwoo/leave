# Leave design read

Derived from the supplied `DESIGN.md`, the brand door/sunlight motif, and the existing product specifications. This records the existing direction rather than introducing a new brand.

Reading this as: a leave-planning service for adult service members, with heavy readable headings, sage surfaces, a green action accent, and calendar-led explanations.

## Dials

- Public landing and guide: **ENERGY 2 / RHYTHM 3 / MOTION 2**. Strong headings establish the product, mixed calendar/explanation/FAQ sections follow the content, and restrained reveals illustrate what changes.
- Signed-in web and native: **ENERGY 1 / RHYTHM 2 / MOTION 2**. Calm data views use predictable lists with summary/detail variation; transitions retain context between states.
- Admin: **ENERGY 1 / RHYTHM 1 / MOTION 2**. Consistent tables prioritize comparison; drawers and feedback transitions explain changes without distracting from operations.

## Decision reasons

- Green identifies the primary action; capacity and errors use their separate semantic colors so brand color does not imply success.
- Heavy display headings supply the supplied brand's friendly voice; compact body type keeps dates and forms legible.
- Calendars explain overlaps directly, while summary/detail columns let people compare records without remembering another screen.
- Spacing groups related dates and separates actions, rather than padding identical feature cards.
- Inputs, record cards, and status pills retain different radii to communicate their roles.
- Shadows distinguish overlays from the underlying task; record rows stay flat.
- Active admin navigation uses a solid pale brand fill and text weight to identify the current destination, without a decorative gradient.
- The database glyph identifies both D1 storage and KV key/value storage; server and send glyphs name API and push services. These icons do not claim measured health.
- Calendar badges show actual capacity state; arrows appear only where they communicate navigation or a real change.
- The open-door/sunlight mark connects the product to leaving and returning; no invented people, customer statistics, or testimonials are needed.
- Native glass follows the supplied platform direction for navigation/overlay accents; content remains readable on solid surfaces.
- Entrance transitions establish new context, calendar flips demonstrate a real capacity threshold, and success feedback confirms completed actions. Reduced-motion preferences replace movement with static states.
- Sample calendar numbers are illustrative, visibly identified as examples, and use the same equality/overflow rule as the product.
- Web remains light as specified; native light/dark themes follow the user's system preference and share tested semantic roles.

Contrast and keyboard changes preserve these decisions while making the interface readable and operable.
